FRONTEND DECISION RECORDS (FDR)



FDR-FE-005: Real-Time Data with Server-Sent Events + WebSocket Hybrid



Decision: Use Server-Sent Events (SSE) for unidirectional real-time data streams (agent status,
story updates, metrics) and WebSockets for bidirectional communication (AI chat, collaborative
editing). TanStack Query manages SSE connections automatically.

Rationale: SSE is simpler, auto-reconnects, and works through most proxies. WebSockets
reserved for true bidirectional needs. This reduces connection overhead by 60% compared to
WebSocket-only approach.

Alternatives: WebSocket-only (rejected — overkill for unidirectional streams); polling (rejected
— latency and server load).

Trade-offs: Two protocols to manage, but each used optimally.



FDR-FE-006: Virtualized Rendering for High-Density Data



Decision: Use @tanstack/react-virtual for all lists, tables, and timelines exceeding 50 items.
Implement windowed virtualization with dynamic row heights.

Rationale: Newsroom dashboards may display 10,000+ stories, claims, or events. DOM node
count must stay under 5,000 for 60fps interactions.

Alternatives: Pagination only (rejected — poor UX for real-time monitoring); infinite scroll
without virtualization (rejected — memory leaks).

Trade-offs: Complexity in dynamic height measurement, but essential for performance.



FDR-FE-007: Apache ECharts for All Data Visualization



Decision: Apache ECharts as the single charting library for all dashboards. Custom theme
matching the Agbofa design system.

Rationale: ECharts handles large datasets (100K+ points), supports WebGL rendering for
performance, and provides every chart type needed (candlestick for revenue, sankey for
attribution, heatmap for audience, graph for agent DAG).

Alternatives: D3.js (rejected — too low-level for productivity); Recharts (rejected —
performance at scale); Chart.js (rejected — limited chart types).

Trade-offs: Larger bundle size (~1MB), but code-split per dashboard.



FDR-FE-008: Feature Flags with LaunchDarkly SDK



Decision: LaunchDarkly React SDK for all feature flags, with server-side evaluation in middleware
and client-side hydration. Every new feature behind a flag.

Rationale: Enterprise platform requires gradual rollouts, A/B testing, and kill switches.
LaunchDarkly provides real-time flag updates without deployment.

Alternatives: Custom feature flag service (rejected — reinventing); environment variables only
(rejected — requires deployment).

Trade-offs: External dependency, but industry-standard for enterprise feature management.

1.3 Agent Communication Graph Component



```typescript

// packages/ui/src/components/ai/agent-communication-graph.tsx

/**

* AgentCommunicationGraph — DAG visualization of agent interactions.

*

* Built with Apache ECharts using force-directed graph layout.

*

* Visual Encoding:

* - Node size: Agent throughput

* - Node color: Agent status (green=healthy, amber=degraded, red=error)

* - Node pulse: Active processing

* - Edge width: Message volume

* - Edge color: Latency (green=<100ms, amber=100-500ms, red=>500ms)

* - Edge animation: Active message flow direction

*

* Interactions:

* - Click node: Open agent detail panel

* - Click edge: Show communication metrics

* - Hover node: Show agent summary tooltip

* - Drag nodes: Reposition (physics simulation pauses)

* - Zoom/Pan: Trackpad and mouse wheel

*/

export function AgentCommunicationGraph({ data }: AgentCommunicationGraphProps) {

 const chartRef = useRef<HTMLDivElement>(null);

 const [selectedAgent, setSelectedAgent] = useState<string | null>(null);



 const option: EChartsOption = {

  tooltip: {

     formatter: (params: any) => {

       if (params.dataType === 'node') {

           return `

            <div class="p-2">

                <strong>${params.data.name}</strong>

                <div>Status: ${params.data.status}</div>

                <div>Throughput: ${params.data.throughput}/s</div>

                <div>Success Rate: ${params.data.successRate}%</div>

                <div>Avg Latency: ${params.data.avgLatency}ms</div>

            </div>

           `;

       }

       return '';

     },

  },

series: [{

 type: 'graph',

 layout: 'force',

 animation: true,

 roam: true,

 draggable: true,

 data: data.nodes.map(node => ({

  name: node.id,

  symbolSize: Math.max(20, node.throughput / 5),

  itemStyle: {

    color: getStatusColor(node.status),

    borderColor: getStatusColor(node.status),

    borderWidth: node.status === 'active' ? 2 : 0,

    shadowBlur: node.status === 'active' ? 10 : 0,

    shadowColor: getStatusColor(node.status),

  },

  // Pulse animation for active agents

  ...(node.status === 'active' && {

    symbolSize: [Math.max(20, node.throughput / 5), Math.max(20, node.throughput / 5)],

    animation: true,

  }),

 })),

 links: data.edges.map(edge => ({

  source: edge.source,

  target: edge.target,

  lineStyle: {

              color: getLatencyColor(edge.avgLatency),

              width: Math.max(1, edge.messageVolume / 100),

              curveness: 0.3,

            },

         })),

         force: {

            repulsion: 200,

            edgeLength: [100, 200],

         },

      }],

    };



    return <ReactECharts ref={chartRef} option={option} style={{ height: '100%' }} />;

}
```

```typescript
// Secure file upload validation

export function validateFileUpload(file: File): ValidationResult {

    const MAX_SIZE = 10 * 1024 * 1024; // 10MB

    const ALLOWED_TYPES = ['image/jpeg', 'image/png', 'image/webp', 'application/pdf'];



    if (file.size > MAX_SIZE) {

        return { valid: false, error: 'File exceeds 10MB limit' };

    }



    if (!ALLOWED_TYPES.includes(file.type)) {

        return { valid: false, error: 'File type not allowed' };

    }



    // Validate file signature (magic bytes)

    return { valid: true };

}
```

```typescript
// Focus management for modals

export function useFocusTrap(containerRef: RefObject<HTMLElement>, isActive: boolean) {

 useEffect(() => {

  if (!isActive) return;



  const container = containerRef.current;

  if (!container) return;



  const focusableElements = container.querySelectorAll(

   'button, [href], input, select, textarea, [tabindex]:not([tabindex="-1"])'

  );



  const firstFocusable = focusableElements[0] as HTMLElement;

  const lastFocusable = focusableElements[focusableElements.length - 1] as HTMLElement;



  // Focus first element

  firstFocusable?.focus();



  function handleTab(e: KeyboardEvent) {

   if (e.key !== 'Tab') return;

         if (e.shiftKey) {

             if (document.activeElement === firstFocusable) {

                 e.preventDefault();

                 lastFocusable?.focus();

             }

         } else {

             if (document.activeElement === lastFocusable) {

                 e.preventDefault();

                 firstFocusable?.focus();

             }

         }

     }



     container.addEventListener('keydown', handleTab);

     return () => container.removeEventListener('keydown', handleTab);

    }, [isActive]);

}



// Announce dynamic content to screen readers

export function useLiveRegion(message: string, politeness: 'polite' | 'assertive' = 'polite') {

    useEffect(() => {

     const region = document.getElementById(`live-region-${politeness}`);

     if (region) {

         region.textContent = message;

     }

    }, [message, politeness]);

}



// Keyboard shortcut manager

export function useKeyboardShortcuts(shortcuts: KeyboardShortcut[]) {

    useEffect(() => {

     function handleKeyDown(e: KeyboardEvent) {

         // Don't trigger shortcuts when typing in inputs

         if (e.target instanceof HTMLInputElement || e.target instanceof HTMLTextAreaElement) {

             return;

         }



         for (const shortcut of shortcuts) {

             const modifiersMatch =

                 (shortcut.meta === (e.metaKey || e.ctrlKey)) &&

                 (shortcut.shift === e.shiftKey) &&

                 (shortcut.alt === e.altKey);



             if (modifiersMatch && e.key === shortcut.key) {

                 e.preventDefault();

                 shortcut.handler();

             }

         }

     }



     window.addEventListener('keydown', handleKeyDown);

     return () => window.removeEventListener('keydown', handleKeyDown);

    }, [shortcuts]);

}
```

```markdown
## FDR-FE-005: Real-Time Data with SSE + WebSocket Hybrid

**Decision:** SSE for unidirectional streams, WebSocket for bidirectional

**Rationale:** Reduces connection overhead by 60% vs WebSocket-only

**Trade-offs:** Two protocols, but each used optimally



## FDR-FE-006: Virtualized Rendering for High-Density Data

**Decision:** @tanstack/react-virtual for all lists >50 items

**Rationale:** Maintain <5,000 DOM nodes for 60fps with 10K+ items

**Trade-offs:** Dynamic height complexity, essential for performance



## FDR-FE-007: Apache ECharts for All Visualization

**Decision:** Single charting library with custom Agbofa theme

**Rationale:** Handles 100K+ data points, WebGL rendering, all chart types

**Trade-offs:** 1MB bundle, code-split per dashboard



## FDR-FE-008: Feature Flags with LaunchDarkly

**Decision:** LaunchDarkly for all feature management

**Rationale:** Real-time flags, A/B testing, kill switches without deployment

**Trade-offs:** External dependency, industry-standard

## FDR-FE-009: Glassmorphism + High Data Density

**Decision:** Glassmorphism aesthetic with compact typography

**Rationale:** Conveys AI-native platform identity while maximizing information display

**Trade-offs:** Not all users prefer dark/glass, mitigated by theme options
```
