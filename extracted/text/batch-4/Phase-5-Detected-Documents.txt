PREAMBLE



This document is the Engineering Constitution for the Agbofa Nexus AI platform. It establishes
the mandatory, non-negotiable rules that govern every line of code produced—whether
generated by AI coding agents (Claude, GPT, Gemini, Codex, Copilot, Cursor, Windsurf) or
written by human engineers.



No code shall be accepted into the repository that violates this constitution.



The 37 volumes of the Agbofa Nexus AI specification define what to build. This document
defines how to build it. Together, they form the complete operating manual for the
implementation phase.

```
│                                                    │

│ 4. ZERO HALLUCINATION POLICY                                    │

│     AI coding agents must not invent APIs, services, or dependencies.            │

│     Every external interface must exist in the specification or be           │

│     explicitly approved through an ADR.                         │

│                                            │

│ 5. OBSERVABILITY IS NOT OPTIONAL                                  │

│   Every service emits structured logs, Prometheus metrics, and                    │

│   OpenTelemetry traces. No exceptions.                            │

│                                             │

│ 6. SECURITY IS EVERYONE'S RESPONSIBILITY                              │

│   No hardcoded secrets. No unvalidated input. No missing auth.                        │

│   Security review is mandatory for all generated code.                    │

│                                            │

│ 7. TESTS ARE NOT OPTIONAL                                 │

│   Every service includes unit tests (>80% coverage), integration tests, │

│   and health checks. Untested code is incomplete code.                        │

│                                            │

│ 8. DOCUMENTATION IS CODE                                      │

│   Every service has a README. Every API is documented. Every ADR is                       │

│   recorded. Documentation is reviewed like code.                      │

│                                            │

│ 9. DETERMINISTIC WHERE POSSIBLE                                   │

│   Business logic must be deterministic. AI/LLM calls are the only                 │

│   acceptable non-deterministic operations, and they must be wrapped                       │

│   with validation and fallback logic.                    │

│                                            │

│ 10. HUMAN OVERSIGHT IS MANDATORY                                      │

│   All AI-generated code must be reviewed by a human engineer before                       │

│   merge to main. No exceptions.                           │

│                                            │
```

```yaml
architectural_discipline:
```

```yaml

error_handling:

 principles:

      - "Errors are values (Go), not exceptions"

      - "Always add context when wrapping errors"

      - "Never swallow errors silently"

      - "Log errors at service boundaries only"

      - "Use structured error types with error codes"



 go:

      wrapping: 'fmt.Errorf("failed to verify claim %s: %w", claimID, err)'

      checking: "errors.Is() and errors.As()"

 python:

      custom_exceptions: "Define domain-specific exception hierarchy"

      context: "raise from original exception"

      format: "DOMAIN-SUBSERVICE-NUMBER"

      examples:

       - "TRUTH-VERIFY-001: Claim verification failed"

       - "DIST-PUB-002: Platform publishing timeout"
```

### 2.2 Why This Order Minimizes Risk



```yaml

risk_mitigation_strategy:

 foundation_first:

      rationale: "All services depend on IAM, configuration, and event bus"

      risk: "Building content services before auth means rework"

      mitigation: "Foundation services complete before any business logic"



 contracts_before_code:

      rationale: "APIs defined before implementation prevents integration surprises"

      risk: "Services built in parallel with incompatible APIs"

      mitigation: "All protobuf contracts reviewed and approved in Week 1"



 shared_libraries_early:

      rationale: "Consistent patterns from the start prevent refactoring"

      risk: "Each service implements its own auth, logging, etc."

      mitigation: "libs/go/ and libs/python/ built before any service"



 vertical_slices:

      rationale: "Complete one pipeline path before expanding horizontally"

      risk: "Many incomplete services, nothing works end-to-end"

      mitigation: "Content Origination → Truth Engine → Story Graph built in sequence"



 frontend_parallel:

      rationale: "Frontend can be built against mock APIs while backend develops"

      risk: "Frontend blocked waiting for backend"

      mitigation: "API contracts enable parallel development with mocked data"

```

## ENTERPRISE ADRs



```markdown

## ADR-EXE-001: Foundation-First Implementation

**Decision:** Build all foundation services before any business logic

**Rationale:** Every service depends on IAM, config, and event bus

**Trade-offs:** Delays visible features, but prevents rework



## ADR-EXE-002: AI Generates, Human Validates

**Decision:** AI coding agents generate initial implementation; humans review

**Rationale:** AI accelerates development; humans ensure quality and prevent hallucinations

**Trade-offs:** Requires human availability, but essential for quality



## ADR-EXE-003: Vertical Slice Integration

**Decision:** Complete one pipeline path before expanding horizontally

**Rationale:** Validates architecture early, catches integration issues

**Trade-offs:** Some services wait, but reduces integration risk

## ADR-EXE-004: Contract-First with Protobuf

**Decision:** All APIs defined in protobuf before implementation

**Rationale:** Enables parallel development, prevents integration surprises

**Trade-offs:** Upfront API design effort



## ADR-EXE-005: Canary Deployments for Everything

**Decision:** Progressive canary deployments for all production changes

**Rationale:** Minimizes blast radius, enables automated rollback

**Trade-offs:** Slower deployments, but essential for reliability

```
